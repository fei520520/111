
我觉得 First-Sight 现在确实到了一个需要重新审视技术路线的阶段，而不是简单地“再优化一下算法”。

结合我们这段时间的讨论，以及我刚刚重新查看的 [First-Sight GitHub 仓库](https://github.com/fei520520/111)，我的判断是：

你们现在的问题不只是区域识别准确率低，而是整个区域建模任务还没有形成一个可以系统验证、迭代的方法。

目前至少有三个问题混在了一起：

1. 区域分割（Segmentation）：连续观察中，什么时候算离开一个区域、进入另一个区域？
2. 区域识别（Recognition）：这次观察到的区域是不是以前来过的？
3. 区域分组（Grouping）：同一个房间里朝不同方向看到的内容，如何归为同一个空间实体？

第三个问题尤其麻烦。你们之前已经发现，图像相似度能够识别重访同一视角，却不能稳定识别同一个房间的不同视角；VLM 也会把两个房间合并，或把一个房间拆开。

这里其实存在信息不足的问题：两个没有共同视觉内容的视角，仅凭各自的单帧图像，通常无法可靠判断它们是否属于同一房间。 必须利用观察之间的连续性、经过的边界、几何关系或者其他空间证据。

而你们此前的尝试，很多仍然在让图像特征或者 VLM 间接承担这个任务。

更严重的是，没有稳定的评估集，就连一次算法修改到底有没有提升，也很难判断。这样做下去，很容易变成反复修改提示词和阈值，却没有可积累的实验结论。

## 一、我找到了一篇很值得你们关注的新论文

[LEXI-SG](https://images.openai.com/static-rsc-4/kVErBYBeR8Xs8mpb3rwIeJNy2MzUYPJbkSHv_cDqaASY_2LP2C-xyiA0nLPo8SEAw0fGcj60S28q9uzMNFVRhkx36AEVGp0wrMQ1cNztxFqnqPZkgwbig8rt6vQVAdyAW4rlx43Fs1hV94w0YjuyQtqFkgooRSWH8oZS8CFCqfY?purpose=inline)

[LEXI-SG: Monocular 3D Scene Graph Mapping with Room-Guided Feed-Forward Reconstruction](https://arxiv.org/abs/2605.13741)

IEEE RA-L，2026 年 9 月发表

仅使用 RGB 视频，不依赖真实深度和相机位姿，完成房间划分、局部三维重建、重访匹配和层次化场景图构建。

它的基本流程是：

连续 RGB 观察

DINO 特征检测区域切换

识别门口、走廊等过渡线索，结合时间迟滞过滤误判

把一个房间的多帧组成一个批次

MapAnything 重建局部几何和相机位姿

重访匹配 + 房间级拓扑图

利用跨房间几何约束进行全局优化

论文使用 RTX 4090 验证了系统，但仍然有明显局限：房间分割的精确率不如依赖深度与位姿的方案，在开放式空间中尤其容易失败。

## 二、先建立一个真正可用的小评估集

我现在最建议你们做的，并不是继续训练模型或者修改图结构，而是先让整个过程可测量。

不用一开始就构建大型 benchmark。可以先选择一层教学楼或办公区域，录制几条第一视角路线。

| 测试场景               | 主要检验           |
| ---------------------- | ------------------ |
| 同一房间原地旋转 360° | 是否错误地拆分房间 |
| 从房间 A 经过门进入 B  | 是否识别区域切换   |
| A → B → A            | 能否识别重访       |
| A → B → C → A       | 能否形成拓扑闭环   |
| 两个布局相似的房间     | 是否错误合并       |
| 开放空间、长走廊       | 区域边界是否稳定   |

初期可以录制 5～10 条路线，总计二三十分钟，保留三路摄像头原始帧和时间戳。

人工只需要标注实际所在区域 ID、区域切换时刻，以及真实的区域邻接关系。

评估指标也要分开：

- 边界检测 F1：进入新区域的时刻是否识别正确。
- 区域分组 ARI / pairwise F1：不同时间的观察是否归属正确，尤其要单独测不同视角的同一区域。
- 重访识别准确率：能否重新找到旧节点。
- 拓扑边 Precision / Recall：建立的相邻关系是否正确。
- 过度分割与错误合并次数：判断模型究竟偏向哪种错误。

尤其建议加入一个 Oracle 实验：人工直接提供正确的区域切换时刻，看看后续区域匹配和拓扑建图还能否正常工作。

如果正确边界下系统效果大幅改善，瓶颈主要就在切换检测；如果仍然失败，则证明分组或者重访机制本身还有问题。

公开数据方面，[HM3DSem](https://aihabitat.org/datasets/hm3d-semantics/) 提供带房间语义的三维环境；[HOV-SG](https://github.com/hovsg/HOV-SG) 还提供从模拟轨迹生成 RGB-D 观察和场景图评估的代码，可以拿来参考。

## 三、架构上，我建议做一个关键改变

不要让系统每看到一张不同的图像，就决定是否创建或合并一个永久性空间节点。

更合理的是分成两层：

第一层：连续观察片段（Episode）

A₁

B₁

C₁

A₂

先依据时间连续性和区域切换证据分段，不急于判断是否属于旧区域。

第二层：稳定的区域拓扑图（Region Graph）

当有足够的视觉、几何及历史连接证据时，才把 A₂ 合并到 A；否则保留不确定性。

最重要的是，节点归属必须允许事后修正，而不是一次 VLM 判断就永久确定。

这也可以保留你此前设想的边上记录历史移动路径的设计。运动数据可以参与短期轨迹约束，但不必强行把它积分成可信的绝对位置。

## 四、我建议现在停止哪些工作

我会暂时停止继续进行开放式 VLM prompt 调参、缺乏验证的阈值修改，以及试图直接设计出一个完美的 place/space 层次结构。

接下来优先做三件事：

1. 用手工标注的切换事件，确认拓扑图构建逻辑本身是否可行。
2. 对比基于时间连续性、视觉边界检测、短时几何约束的几种分组方案。
3. 只有确认这些方案具体失败在哪里，再决定引入更大的预训练视觉模型或专门训练。

这里还有一个很重要的现实问题：“一个区域”的定义本身必须固定。 封闭房间相对容易，但开放式办公室、客厅与餐厅连通区域、长走廊应该如何划分，并不存在唯一的天然答案。评价集必须先确定规则，否则算法正确与否根本无法判定。

## 最后，我对项目现状的判断

我不认为现在就应该砍掉 First-Sight，但我也不赞成继续这样没有评估地探索。

你们已经在真实设备上碰到了一个很有价值的问题：如何在不可靠位移、有限视野和低成本硬件条件下，构建稳定的空间记忆。这不是一个简单的工程 Bug，也不是 VLM 换成更强的模型就一定能解决的。

但现在有两条路需要区分：

如果目标是做出能用的软件，应该设立明确的区域识别准确率目标，优先支持有明确边界的室内空间，必要时接受人工纠错和系统无法识别的情况。

如果目标是科研，那么区域分组失败、切换检测不稳定、错误合并难以恢复，反而可以作为可研究的问题。不过前提仍然是建立评估和基线。

我更倾向于你们目前采取一个折中方案：先用一套小规模真实场景评估，将 First-Sight 的区域识别单独做成可以反复测试的模块。

只要这一步做成，即使某个算法彻底失败，你们也能知道它为什么失败、失败得有多严重、下一个方案究竟有没有改善。

这和现在原地踏步的状态会有本质区别。
